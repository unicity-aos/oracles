## Oracle 2026.10.0

Changes since the published 2026.9.2 release (net user-facing behavior):

### Added

- Register native client event coverage for Codex, Claude Code and Grok through
  the Oracle adapter. Preserve each client's supported event and decision
  semantics while forwarding canonical events to the AOS-owned hook adapter.
- Expose signed Oracle update discovery and distinguish installed plugin bytes
  from host registration and session activation. New installation reports which
  host principals were successfully provisioned.

### Fixed

- Return native policy decisions through the client hook path, including
  decision-returning tool hooks, rather than treating additional context as a
  blocking decision. Preserve protected hook-registration custody.
- Restore nonblocking update notices during host startup without delaying
  normal session initialization for a remote version check.

- Recover an already-installed stopped runtime for Claude binding hooks and keep
  it persistent between calls, including immediate valid retry after a refused
  token. Startup and policy delivery remain bounded by the native hook deadline.
- Reconcile recognized stale default AOS dependencies after a product upgrade
  through the signed distribution; reject unknown identities before mutation.
- Mint private per-session hook tokens on minimal hosts using the existing
  Python interpreter when OpenSSL is unavailable. Preserve session isolation
  and retirement without requiring an extra token-generator package.

The twelve-asset host adapter inventory is unchanged. Oracle does not publish
AOS-owned capsules. The authenticated runtime compatibility contract remains a
minimum version, not an exact-version ceiling. Actual installed executables are
verified against their own signed AOS inventory. Clients only receive the hooks
and interaction features their host protocol supports.
